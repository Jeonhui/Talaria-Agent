# Customization Guide

Fork this repo and rebrand it for your own agent. Most visible identity lives
in a single file: `talaria_cli/branding.py`. Edit it once and the whole CLI
re-skins.

This guide covers, in order of impact:

1. [Quick rebrand — `branding.py`](#1-quick-rebrand--brandingpy)
2. [Package metadata](#2-package-metadata)
3. [Skin system (per-user themes)](#3-skin-system-per-user-themes)
4. [Banner layout toggles](#4-banner-layout-toggles)
5. [Optional infrastructure rename](#5-optional-infrastructure-rename)
6. [External integrations](#6-external-integrations)
7. [Remaining hardcoded strings](#7-remaining-hardcoded-strings)

## 1. Quick rebrand — `branding.py`

Open `talaria_cli/branding.py`. Every constant in this file is a default that
the rest of the codebase reads through helper functions, so edits propagate
automatically without touching call sites.

### 1.1 Brand emoji

```python
BRAND_EMOJI = "🦅"   # appears in status bar, response label, prompt working state
```

### 1.2 ASCII art

```python
BANNER_LOGO = """[bold #FFD700]
... your block logo (Rich markup OK)
[/]"""

BANNER_HERO_ART = """[bold #FFD700]... hero art line 1[/]
[bold #FFD700]... hero art line 2[/]
..."""
```

`BANNER_LOGO` shows above the panel on terminals ≥95 columns wide.
`BANNER_HERO_ART` lives in the left column of the welcome panel.

### 1.3 Color palette

The shipped default is the **Sky Messenger** palette (deep sky blue,
cloud-white text, silver/cyan accents — matching the Hermes / winged-
sandal theme without the warm-gold treatment). Replace any value to
re-skin.

```python
DEFAULT_COLORS = {
    # Sky Messenger
    "banner_border":   "#1E5A88",  # deep sky blue — panel frame
    "banner_title":    "#E8F4FF",  # cloud white — version label
    "banner_accent":   "#5DADE2",  # bright sky blue — section headers
    "banner_dim":      "#5A7894",  # muted slate-blue — labels, separators
    "banner_text":     "#EAF6FF",  # soft cloud white — body text
    "ui_accent":       "#7FCDEE",  # cyan-silver
    "ui_label":        "#A8C9DD",  # silver-blue
    "ui_ok":           "#7FB39C",  # sage mint — success
    "ui_error":        "#D86B6B",  # dusty coral — error
    "ui_warn":         "#E8C770",  # pale gold — warning
    "prompt":          "#EAF6FF",  # matches banner_text
    "input_rule":      "#1E5A88",  # matches banner_border
    "response_border": "#5DADE2",  # sky blue — response box border
    "status_bar_bg":   "#0F1E33",  # deep night sky
    "session_label":   "#A8C9DD",
    "session_border":  "#456079",
}
```

Used throughout banner, status bar, response box, prompt input area.

For a different mood, swap the whole dict — e.g. ``Greek marble`` (white
+ deep navy), ``Mediterranean dusk`` (terracotta + sea blue), etc.

### 1.4 Branding strings

```python
DEFAULT_BRANDING = {
    "brand_emoji":      BRAND_EMOJI,
    "agent_name":       "Aether Agent",        # full name
    "agent_short_name": "Aether",              # one-word brand
    "welcome":          "Welcome to Aether! Type your message or /help for commands.",
    "goodbye":          f"Bye! {BRAND_EMOJI}",
    "response_label":   f" {BRAND_EMOJI} Aether ",
    "prompt_symbol":    "▶",
    "help_header":      "(★) Commands",
}
```

`agent_name` and `agent_short_name` flow into status bar, panel titles,
update messages, OpenRouter `X-OpenRouter-Title` header, Discord User-Agent,
email subject lines, and admin script output.

### 1.5 Spinner faces and verbs

```python
DEFAULT_WAITING_FACES   = ["(>_<)", "(◕‿◕)", ...]
DEFAULT_THINKING_FACES  = ["(◔_◔)", "(¬‿¬)", ...]
DEFAULT_THINKING_VERBS  = ["pondering", "computing", ...]
```

Shown during agent activity. Skins can override these too — see §3.

### 1.6 Repository URLs

```python
DEFAULT_REPO_URL          = "https://github.com/<you>/<fork>.git"
DEFAULT_REPO_HTTPS_URL    = "https://github.com/<you>/<fork>"
DEFAULT_RELEASE_URL_BASE  = "https://github.com/<you>/<fork>/releases/tag"
DEFAULT_INSTALL_SCRIPT_URL = "https://raw.githubusercontent.com/<you>/<fork>/main/scripts/install.sh"
```

Used by the update checker, release link in the banner title, install
prompts in setup/uninstall messages, OpenRouter `HTTP-Referer` header, and
Discord User-Agent.

### 1.7 Agent identity prompt (SOUL.md + system prompt)

The "You are <Agent>, an intelligent AI assistant..." identity blurb is
now generated by ``build_agent_identity()`` in ``branding.py``. It feeds
two places:

- ``~/.talaria/SOUL.md`` — seeded once on first run, then user-editable.
- The system prompt assembled every turn (when ``SOUL.md`` is missing).

```python
def build_agent_identity(user_name: str = "") -> str:
    agent = DEFAULT_BRANDING.get("agent_name", "Talaria Agent")
    body = (
        f"You are {agent}, an intelligent AI assistant. "
        "You are helpful, knowledgeable, and direct. ..."
    )
    if user_name:
        body += f" You are working with {user_name}."
    return body
```

To rebrand the identity blurb, edit the body above. The opening
"You are <agent_name>" sentence pulls from ``DEFAULT_BRANDING["agent_name"]``
automatically — usually you don't need to touch the body.

### 1.8 Optional `user.display_name` (greet a known user)

End users can opt in to a personalized identity prompt by adding a
display name to their ``~/.talaria/config.yaml``:

```yaml
user:
  display_name: "Johnny"
```

When present, the seeded ``SOUL.md`` and the runtime system prompt both
append "You are working with Johnny." to the identity blurb.

When absent, the agent doesn't auto-pull the OS username — empty by
default, opt-in only.

A read helper is available for any code that wants the configured name
(e.g. banner custom lines, response prefixes):

```python
from talaria_cli.config import get_display_name
name = get_display_name()           # config value, then OS user, then "user"
name = get_display_name(default="") # config value only; "" if not set
```

#### Reseeding ``SOUL.md`` after a config change

``SOUL.md`` is seeded **once** on first run and is never overwritten —
that's intentional, so users can edit it freely without losing changes
on update. The runtime system prompt always reflects the current
``user.display_name``, so a stale SOUL.md only matters for the first
turn of a brand-new session that hasn't loaded SOUL.md yet (rare).

To regenerate the seeded SOUL.md after changing ``display_name``:

```bash
rm ~/.talaria/SOUL.md           # delete the existing file
python -m talaria_cli.main      # next launch reseeds with the new value
```

If you've customized SOUL.md manually, back it up first.

### 1.9 Custom banner lines

Add arbitrary text inside the right column of the welcome panel.

```python
DEFAULT_BANNER_CUSTOM_LINES = [
    "[bold]Welcome back![/]",
    "User: johnny",
    "[#FF8C00]⚠ Beta build[/]",
]

DEFAULT_BANNER_CUSTOM_POSITION = "top"   # or "bottom"
```

- Each list entry is one line. Rich markup is preserved.
- Empty list removes the section entirely.
- ``"top"`` places the lines above ``Available Tools``;
  ``"bottom"`` places them after the ``N tools · N skills`` summary
  (and before any update warning).
- Toggle the whole section off via ``DEFAULT_BANNER_LAYOUT["show_custom"] = False``.

Skin-level override (``~/.talaria/skins/<name>.yaml``):

```yaml
banner_custom_lines:
  - "[bold]Production environment[/]"
  - "Slack: #ops-alerts"
banner_layout:
  show_custom: true
```

Want a dynamic line (e.g. greet by name)? Build it in code where you
seed ``DEFAULT_BANNER_CUSTOM_LINES`` — it's just a Python list:

```python
from talaria_cli.config import get_display_name
DEFAULT_BANNER_CUSTOM_LINES = [
    f"Welcome back, {get_display_name(default='friend')}!",
]
```

### 1.10 Test the rebrand

```bash
python -m talaria_cli.main           # start the CLI; the banner should reflect new colors/strings
talaria version                      # version line uses new agent_name
talaria status                       # status header reflects rebrand
```

## 2. Package metadata

These live outside `branding.py` because they describe the package itself,
not its visual identity.

### 2.1 Version

`talaria_cli/__init__.py`:

```python
__version__      = "0.3.0"
__release_date__ = "2026.5.5"
```

The banner version line and `talaria version` command both read from here.

### 2.2 `pyproject.toml`

```toml
[project]
name        = "aether-agent"
description = "Your agent description"
authors     = [{ name = "You", email = "you@example.com" }]

[project.urls]
Homepage   = "https://github.com/<you>/<fork>"
Repository = "https://github.com/<you>/<fork>"

[project.scripts]
aether = "talaria_cli.main:main"   # rename CLI command — see §5 for full rename
```

### 2.3 `README.md` and `LICENSE`

Replace as appropriate. The default `LICENSE` should stay if you keep the
upstream license terms — only change the copyright holder line.

## 3. Skin system (per-user themes)

`branding.py` sets the *default* identity. End users (and you) can install
extra skins to ship multiple looks.

### 3.1 Built-in skins

Defined in `branding.py` as `ALTERNATE_SKINS`:

```python
ALTERNATE_SKINS = {
    "mono": { ... },
    "dark": { ... },   # add as many as you want
}
```

`skin_engine.py` merges these with the default skin automatically.

### 3.2 User-installed skins (YAML)

End users can drop a YAML file in `~/.talaria/skins/<name>.yaml`:

```yaml
name: ocean
description: Cool blue ocean theme

colors:
  banner_title: "#00BFFF"
  banner_accent: "#1E90FF"
  banner_text:   "#E0FFFF"

branding:
  brand_emoji:    "🌊"
  agent_short_name: "Ocean"
  welcome:        "Welcome to the deep!"

banner_logo: |
  custom block logo

banner_hero: |
  custom hero art line 1
  custom hero art line 2

banner_layout:
  show_skills: false
  show_update_warning: false

spinner:
  waiting_faces:
    - "(~‿~)"
    - "(>‿<)"
  thinking_verbs:
    - "diving"
    - "swimming"
```

Activate at runtime:
```
/skin ocean
```

Or persist via `~/.talaria/config.yaml`:
```yaml
display:
  skin: ocean
```

### 3.3 Override priority

```
skin YAML  >  branding.py default  >  hardcoded fallback
```

Anything missing from a skin falls through to `branding.py`. Anything
missing from `branding.py` falls back to a literal default in code (used
when imports fail).

## 4. Banner layout toggles

Hide entire sections of the welcome banner without forking the renderer.

`branding.py`:

```python
DEFAULT_BANNER_LAYOUT = {
    "show_logo":           True,   # large ASCII block logo (≥95 col terminals)
    "show_hero_art":       True,   # left-column hero art
    "show_model":          True,   # model name + context length
    "show_cwd":            True,   # current working directory
    "show_session_id":     True,   # "Session: <id>" line
    "show_custom":         True,   # custom user lines (DEFAULT_BANNER_CUSTOM_LINES)
    "show_tools":          True,   # "Available Tools" section
    "show_mcp_servers":    True,   # "MCP Servers" section
    "show_skills":         True,   # "Available Skills" section
    "show_profile":        True,   # "Profile: <name>" line
    "show_summary":        True,   # "N tools · N skills · /help..." footer
    "show_update_warning": True,   # "⚠ N commits behind" line
}
```

Set any value to `False` to drop that section.

When one column is empty (e.g. only `show_hero_art=True`, or only
`show_custom=True`), the banner auto-collapses to a single centered column
so the populated side doesn't hug the edge.

### Skin-level override

```yaml
banner_layout:
  show_logo: false
  show_skills: false
```

Only the keys you list override the default; missing keys inherit from
`branding.py`.

## 5. Optional infrastructure rename

Deeper than visual rebrand. Change these only when fork users would conflict
with the upstream install (shared `~/.talaria/` data, same `talaria` command).

### 5.1 Home directory `~/.talaria/`

`talaria_constants.py` — `get_talaria_home()`. The default uses `.talaria`;
change the directory name to e.g. `.aether`.

⚠️ Existing users will lose access to their config/sessions/skills until they
migrate. Consider shipping a one-time migration script.

### 5.2 Environment variable prefix

Codebase uses `TALARIA_HOME`, `TALARIA_REVISION`, `TALARIA_PROFILE`, etc.
A full rename touches `talaria_constants.py`, install scripts, gateway
service files, and docs. Search:

```bash
grep -rn "TALARIA_" --include="*.py" --include="*.sh" --include="*.toml"
```

### 5.3 CLI command name

`pyproject.toml` `[project.scripts]`:
```toml
aether = "talaria_cli.main:main"
```

The user types `aether ...` instead of `talaria ...`. Help text references
to `talaria <subcommand>` (in argparse `description=`/`help=`) should also
be updated by hand:

```bash
grep -rn "talaria " talaria_cli/main.py
```

### 5.4 Module name `talaria_cli`

Don't. The cost-to-benefit ratio is terrible. Imports across the entire
codebase, gateway adapters, agent prompt builder, scripts — all reference
`talaria_cli`. Leave it as the implementation namespace; users see only
the CLI command name.

## 6. External integrations

These have already been wired through `branding.py`, but each external
system has its own registration step that you must redo on a fork:

| Integration | What changes | What you must do |
|-------------|--------------|------------------|
| OpenRouter `X-OpenRouter-Title` | `agent_name` from branding | Your fork now appears as a separate app on OpenRouter usage dashboards |
| OpenRouter `HTTP-Referer` | `DEFAULT_REPO_HTTPS_URL` | Match a real URL or remove |
| Discord User-Agent | Derived from `agent_name` + URL | No registration needed; Discord just logs it |
| MCP OAuth `client_name` | Hardcoded "Talaria Agent" in `tools/mcp_oauth.py` | Re-register OAuth clients on each MCP server with your new name |
| Anthropic adapter compat | Hardcoded "Talaria Agent" → "Claude Code" mapping | Leave alone unless you also retarget the adapter |
| Spotify OAuth | `SPOTIFY_DOCS_URL` from branding | Update the redirect URL in your Spotify developer dashboard |

## 7. Remaining hardcoded strings

A handful of user-facing strings still contain "Talaria" or "Talaria Agent"
literally — mostly argparse `--help` / `description=` text in
`talaria_cli/main.py`, plus a few admin-script prose lines (uninstall,
gateway, doctor, status). They aren't routed through `branding.py` because
the volume is large and per-message context matters.

For a quick fork rebrand, a `sed` sweep is usually enough:

```bash
# Preview first
grep -rn 'Talaria Agent' talaria_cli/ agent/ gateway/ tools/ scripts/

# Replace if the diff looks right
grep -rl 'Talaria Agent' talaria_cli/ agent/ gateway/ tools/ scripts/ \
  | xargs sed -i '' 's/Talaria Agent/Aether Agent/g'   # macOS
# (Linux: drop the empty arg after -i)

grep -rl '\bTalaria\b' talaria_cli/ agent/ gateway/ tools/ scripts/ \
  | xargs sed -i '' 's/\bTalaria\b/Aether/g'
```

⚠️ Review the diff before committing. The `\b...\b` word boundary protects
URLs, module names (`talaria_cli`), env vars (`TALARIA_*`), and install
paths (`.talaria/`), but a manual scan is wise.

Some persona-specific strings (e.g. "Captain Talaria" in the pirate persona
in `cli.py`) are intentionally character-themed — leave them or rewrite for
your brand persona.

---

## TL;DR for a fast fork

1. Edit `talaria_cli/branding.py` — colors, art, names, URLs, spinner.
2. Bump `talaria_cli/__init__.py` and `pyproject.toml`.
3. (Optional) `sed` sweep §7 for any leftover argparse text.
4. Reinstall (`pip install -e .` or your install script) and run.

Steps 4–6 are only worth it for forks that need to live alongside the
upstream install or fully separate their identity.
